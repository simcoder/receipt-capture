# 002 — Receipt capture UX

Status: written on 2026-10-30. Not built.

The spend app is the reference for layout only: a home list, a round center camera button, and a library pick that continues into a form. This app does not take spend’s AI classify, properties, banks, or inbox.

The screens change. The rules do not. Statuses, integer minor units, `MM-DD-YYYY` dates, idempotency, company isolation, the local fake when the API cannot be reached, logout clearing the device queue, and match confirmation stay as shipped in [001-initial-poc.md](001-initial-poc.md) and [DECISIONS.md](../DECISIONS.md) D1–D19. This spec does not add a new submit path, a new status, or an edit of a submitted receipt.

NeedsReview opens the receipt so the user can confirm the open transaction. Merchant, amount, currency, and date stay as submitted.

## Flow

Sign in, then the home list loads `GET /receipts` for that company. The center button opens the camera. Upload from the library, or **Use a fake receipt** (cafe, fuel, or office), opens the same form. The iOS Simulator has no camera, so the fake receipt is the simulator path. Submit is the existing queue and submit. The receipt then shows on the home list with its existing status. A NeedsReview row opens that receipt to confirm the match.

Logout still clears the in-memory list, the device queue, the local fake, and the tokens. The next sign-in fills the home list from the API. Receipts that reached the API come back. Receipts that never reached the API are gone.
